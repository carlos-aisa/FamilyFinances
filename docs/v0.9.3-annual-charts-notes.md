# v0.9.3 Annual Charts Notes

## Summary

Version `0.9.3` adds annual chart visualizations to the reporting area while keeping tables as the canonical source of truth.

## User-visible changes

- Evolution visuals are integrated in existing reports:
  - `Economic State` -> `Asset Evolution` tab
  - `Account Totals` -> `State Evolution` tab
  - `Account Group Totals` -> `State Evolution` tab
- A dedicated `Monthly Evolution` report page is no longer part of the UI entry flow.
- Annual charts are rendered with `Chart.js` (line and pie composition).
- `Asset Total` shows one line chart with monthly `End Balance`.
- `Account Groups` state evolution includes:
  - multi-series monthly evolution line chart
  - pie chart (`quesitos`) for expense-oriented group composition
- `Accounts` state evolution includes:
  - line evolution chart by account (top deterministic set or one selected account)
  - composition charts by account nature for `Expense` and `Income`
- Chart-specific loading/empty/error states are explicit and non-blocking for filter changes.

## Data and semantics

- Chart datasets are derived from the same `MonthlyEvolutionReportDto` points used by table rows.
- Primary numeric source endpoint is `GET /api/v1/reports/state-evolution`.
- Legacy alias `GET /api/v1/reports/monthly-evolution` remains available for compatibility.
- Series ordering is deterministic (`DisplayName`, then `SeriesKey`) to keep stable chart identity across reloads.

## Known visualization limitations

- Multi-series evolution charts are capped to top `12` deterministic series for readability.
- Account-group composition currently targets expense-oriented groups.
- Account-group composition depends on account-group nature lookup in Web layer; when lookup is unavailable, composition falls back to loaded group series.
- Liability accounts are excluded from account-group monthly evolution aggregation.
- Annual charts in `0.9.3` are year-to-date only; intra-month/daily charts are deferred to `0.9.4`.
