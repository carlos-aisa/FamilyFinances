# v0.6.5 - Account Reconciliation Implementation Summary

## Overview

This version implements account reconciliation functionality, allowing users to adjust account balances without modifying historical transactions. This addresses the critical need to fix mismatches between computed and actual balances in a clean, auditable way.

---

## ?? Objectives Achieved

### ? Must-Have Features
- **Reconcile Action**: Available on account movements page with dedicated button
- **Reconcile Form**: Fields for actual balance, as-of date, and optional note
- **Adjustment Behavior**: 
  - Computes difference between actual and computed balance
  - Creates adjustment transaction if difference exists
  - Shows informational message when already reconciled
  - Uses dedicated "Balance Adjustments" accounts (auto-created if missing)

### ? Technical Requirements
- No new tables (reuses existing Transaction/TransactionSplit entities)
- Never modifies historical transactions
- Works with Asset and Liability accounts only
- Proper accounting sign conventions maintained
- Comprehensive error handling and validation

## ?? Implementation Details

### Accounting Logic

**Split Sign Convention:**
- For Asset accounts: 
  - Negative split = money in (increases balance)
  - Positive split = money out (decreases balance)
- Balance = raw sum of all split amounts

**Adjustment Calculation:**
```
difference = actualBalance - computedBalance
targetSplitAmount = difference
adjustmentSplitAmount = -difference (must balance to zero)
```

**Adjustment Account Selection:**
- If `targetSplitAmount < 0`: Use Income adjustment account (money coming in)
- If `targetSplitAmount > 0`: Use Expense adjustment account (money going out)

### API Contract

**Request:**
```json
POST /api/v1/accounts/{accountId}/reconcile
{
  "actualBalance": 100.50,
  "asOfDate": "2026-01-15",
  "note": "Bank statement reconciliation"
}
```

**Response (Success):**
```json
{
  "adjustmentCreated": true,
  "transactionId": "guid",
  "computedBalance": 120.00,
  "actualBalance": 100.50,
  "difference": -19.50,
  "message": "Balance decreased by $19.50"
}
```

**Response (Already Reconciled):**
```json
{
  "adjustmentCreated": false,
  "transactionId": null,
  "computedBalance": 100.50,
  "actualBalance": 100.50,
  "difference": 0,
  "message": "Account already reconciled. No adjustment needed."
}
```

### Error Responses

- **404 Not Found**: Account doesn't exist
- **400 Bad Request**: Account is not Asset/Liability type, or account is closed
- **401 Unauthorized**: Missing/invalid authentication token

## ?? Usage Flow

1. User navigates to Account Movements page (`/accounts/{id}/movements`)
2. Clicks "Reconcile" button in header
3. Modal appears with form
4. User enters:
   - Actual balance from bank statement/wallet
   - Date when balance was accurate
   - Optional note
5. Clicks "Reconcile" button
6. System:
   - Computes current balance as of date
   - Calculates difference
   - Creates adjustment transaction if needed
   - Shows success message with details
7. Movements list refreshes to show new adjustment transaction
