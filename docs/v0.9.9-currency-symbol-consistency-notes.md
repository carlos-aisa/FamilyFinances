# v0.9.9 Currency Symbol Consistency Notes

## Summary

This update hardens money presentation consistency in the Web UI so monetary values are rendered with EUR identity (`€`) across list and table views.

## User-visible changes

- Transactions list (`/transactions`) renders amount badges using EUR formatting semantics.
- Account movements list (`/accounts/{id}/movements`) keeps EUR rendering for both signed amount and running balance.
- Historical lists (`/history/transactions` and `/history/movements`) now use the same centralized EUR formatter.
- Representative reporting table assertions were reinforced to prevent `$` regressions.

## Localization behavior contract

- Active UI culture still controls numeric and date conventions (group separators, decimal separators, localized month/day names).
- Currency identity is fixed to EUR for domain monetary values.
- Rendering paths that could inherit foreign currency symbols from culture defaults are avoided for ledger amounts.

## Backward compatibility

- API routes, request/response DTO shapes, and persistence storage are unchanged.
- The change is presentation-only for currency symbol consistency.

## Verification highlights

- Web tests assert euro-formatted output in transactions, account movements, and historical list pages.
- Money formatter tests explicitly guard against `$` in both `es-ES` and `en-US` formatting contexts.
- Representative reporting tests include a regression check that rendered markup does not contain `$`.
