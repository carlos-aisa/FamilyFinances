# v0.9.8 UI Full Views Review Notes

## Scope Summary
- Full UI/presentation review applied across dashboard, reports, accounts, quick entry, transactions, history, payees, and login.
- Visual consistency updates focused on shared button/accordion primitives, report panel alignment, and chart styling parity.
- Navigation continuity updated for transaction detail/edit flows using whitelisted origin context instead of free-form return URLs.
- No report formula changes and no backend schema migration.

## Updated UX Flows
- Dashboard uses explicit current-month wording and keeps fixed current-month context.
- Accounts view uses a reusable single-open accordion and replaces per-group month footers with one page-level `updated as of` message.
- Quick Entry adds:
  - one global account search box above grouped accounts,
  - single-open accordion account groups,
  - configurable per-mode guidance text in header area,
  - shared selected-date state preserved when switching modes.
- Payees now render as a responsive card grid (name + rename + delete) with existing search behavior preserved.
- Transactions list now exposes a dedicated `Payee` column and keeps description/subheadline clean (no payee duplication).
- Category Totals and Account Totals rows drill down to account movements with report-origin metadata and period context.
- Economic State evolution tabs (Asset/Income/Expense) use a 3-column analytical layout:
  - monthly table,
  - composition pie,
  - chart stack.
- Login remembers only the last successful username and prefills it on later visits.

## Transaction Navigation Context Tokens
- Implemented in `TransactionOriginContext` with safe parsing/serialization and fallback behavior.
- Allowed origin tokens:
  - `transactions`
  - `accounts-movements`
  - `history-transactions`
  - `history-movements`
  - `report-category-totals`
  - `report-account-totals`
- Supported typed optional query values:
  - `accountId` (`Guid`)
  - `from` (`DateOnly`)
  - `to` (`DateOnly`)
  - `year` (`int`)
- Unknown/invalid tokens default to `transactions` and never redirect to arbitrary URLs.

## Chart Cutoff Semantics
- Monthly charts:
  - full month axis always rendered for month-focused views,
  - payload includes `markerDay` + `totalDays`,
  - JS renderer applies cutoff marker and de-emphasized future segment.
- Annual charts:
  - fixed 12-month axis (Jan-Dec),
  - payload includes `markerMonth` + `totalMonths`,
  - JS renderer applies month cutoff marker and future-area de-emphasis only when applicable.
- Export buttons in chart components use shared rectangular app button shape.

## Economic State Composition Rules
- Composition pie in Asset/Income/Expense evolution tabs is month-focused.
- Data source: account evolution (`scope=accounts`) filtered by account nature.
- Slice policy:
  - top 10 contributors by magnitude shown individually,
  - remaining contributors aggregated into `Others`.
