# v0.9.5 Reporting Insights Notes

## Summary

Version `0.9.5` adds deterministic reporting insights focused on explainability:

- Pareto ranking (top contributors)
- concentration indicators (top-N coverage over total)
- monthly anomaly indicators with explicit baseline/threshold metadata
- dimension toggle for `group` and `payee`

## Where It Appears

- `Period Summary` (`/reports/monthly-summary`)
  - New `Period Insights` card
  - Toggle: `Groups` / `Payees`
  - Collapsible details for rankings and anomaly breakdown

## Contracts

- `GET /api/v1/reports/insights/pareto`
  - Returns `ReportingParetoInsightsDto`
  - Includes both `Expense` and `Income` sections
- `GET /api/v1/reports/insights/anomalies`
  - Returns `ReportingAnomalyInsightsDto`
  - Evaluates one month and one nature (`Expense` or `Income`)

## Formula Notes

### Pareto ranking

- Per-contributor amount: absolute magnitude in cents (`abs(amount)`).
- Total denominator: sum of all contributor magnitudes for the selected nature and period.
- Contribution percentage:

```text
contribution_pct = contributor_amount / total_amount * 100
```

- Top-N coverage:

```text
top_n_coverage_pct = sum(top_n_amounts) / total_amount * 100
```

### Anomaly evaluation

For each contributor in the focused month:

1. Build history window from previous `lookbackMonths`.
2. Compute baseline mean (`mu`) and standard deviation (`sigma`) over that window.
3. Threshold:
   - if `sigma > 0`: `threshold = mu + 2 * sigma`
   - if `sigma == 0`: `threshold = mu * 1.25`
4. Flag anomaly when:

```text
current_amount > threshold
```

### Insufficient history guardrail

- Count active history months (months with non-zero contributor amount).
- If active months `< requiredHistoryMonths`:
  - contributor state is `Insufficient history`
  - contributor is **not** flagged as anomaly

## Interpretation Guidance

- Use Pareto to answer: "who explains most of my expense/income?"
- Use concentration to answer: "how dependent am I on a few contributors?"
- Use anomaly to answer: "is this month unusually high vs baseline?"
- An anomaly is a signal for review, not an automatic error.
