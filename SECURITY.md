# Security Policy

## Supported Versions

Security fixes are prioritized on the active development line and latest release artifacts.

| Version line | Supported |
| --- | --- |
| `main` latest release | Yes |
| `develop` | Best effort |
| Older tags | No |

## Reporting a Vulnerability

Please do not open public issues for sensitive vulnerabilities.

Send a private report with:

- affected component(s),
- impact summary,
- reproduction steps,
- proof-of-concept (if available),
- proposed mitigation (optional).

Preferred channel:

- Open a private security advisory in GitHub (`Security` tab) for this repository.

If private advisory is not available in your context, open a minimal issue requesting a secure contact channel without disclosing exploit details.

## Response Targets

- Initial acknowledgment: within 3 business days.
- Triage and severity classification: within 7 business days.
- Remediation target:
  - Critical/High: as soon as possible, typically first patch window.
  - Medium/Low: scheduled based on risk and release cadence.

## Disclosure Policy

- Coordinated disclosure is preferred.
- Public disclosure should happen after a fix is released or mitigation is available.
